# 移植到其他设备

先说实话：这套方法只在一种设备上完整做过，就是**小米智能音箱 Pro（OH2P），固件 1.62.2**。别的型号、别的牌子我们没有试过。下面写的是换一台设备要做哪些事、哪些能直接搬、哪些要重新摸，**不是说照着做一定能成**。

原理先看[原理](原理.md)，下面的"第几节"指那篇文章里的小节。

## 先判断能不能做：五个问题

1. **能不能拿到最高权限，并让自己的程序开机自动运行？**这是最关键、也最难的一步。
   - 小米的其他型号：先去 [open-xiaoai](https://github.com/idootop/open-xiaoai) 和 [xiaoai-plus](https://github.com/kslr/xiaoai-plus) 看有没有人做过你的型号。
   - 小度、天猫精灵等别的牌子：我们不知道有公开、可靠的办法。没有经过验证的方法，不要拿自己的音箱乱试刷机。
2. **里面是什么系统、什么 CPU？**我们的程序编译成 32 位 ARM（armv7，硬浮点），静态链接，不依赖音箱里的库。同类 ARM Linux 设备大概率能直接跑；不是的话，要改[交叉编译配置](../xiaoai-plus/armv7-linux-gnueabihf.cmake)和 [toolchain/](../xiaoai-plus/toolchain/)。
3. **麦克风能不能和原来的语音助手同时读？**能读才能像我们这样两个助手并存。不能的话，只能停掉原来的语音助手，代价是它没法用了。
4. **喇叭能不能和原来的助手共用？**要能放声音，最好还能共用一个音量控件。
5. **资源够不够？**可写分区要有几十 MB 空间；待机要一直跑唤醒识别（OH2P 上大约占一个 CPU 核的八成）。

## 换设备要改哪些地方

| 要做的事 | OH2P 上的做法 | 在哪里改 |
|---|---|---|
| 拿权限、开机自启（第 1 节） | USB 刷机模式写 system0，开机脚本 `rc.local` 调 `boot.sh` | `setup/02`–`07`、`setup/build_minimal_patch.py` |
| 在局域网里找到设备 | 按米家 App 里的 MAC 地址找 | `setup/08-find-speaker.sh` |
| 录音（第 2 节） | `arecord -D noop`，32 位，取波束成形那一路，右移 16 位 | `src/config/config.hpp` 的 `input_device`；`config.ini` 的 `[wakeup] s32_shift`、`input_channel`；`src/audio/recorder_arecord.cpp` |
| 放音（第 2 节） | `aplay -D default`，24kHz 单声道 | `src/audio/player_aplay.cpp` |
| 音量（第 2 节） | `amixer -c 0` 调 `mysoftvol` | `src/audio/volume.hpp` |
| 给原来的助手让路（第 2 节） | 读 `/tmp/log/messages` 里 `mipns-xiaomi` 的唤醒记录；用 `mphelper` 暂停音乐 | `src/app/native_wake_monitor.cpp`、`src/app/app.cpp` |
| 借原来的嗓子播报（第 2 节） | `/usr/sbin/tts_play.sh` | `src/app/app.cpp` |
| 开机守护 | `boot.sh` 等网络、崩溃重启 | `xiaoai-plus/boot.sh` |
| 唤醒灵敏度（第 3 节） | 门槛 0.10，自动增益开 | `config.ini` 的 `[wakeup]`、`keywords/` |

路径都相对 `xiaoai-plus/`，`setup/` 除外。

## 不用改、可以直接搬的

- 和豆包实时对话：`src/realtime/`。只要设备能联网、能录 16kHz 单声道、能放 24kHz 单声道。
- 提示词、认人和记忆：`src/memory/`。
- 记忆后台和家长页：`server/`。它和音箱是什么型号无关。

## 用 Windows 电脑

`setup/` 里的脚本是按 Mac 写的。和电脑系统有关的主要是刷机那几步（04–07）用的 USB 工具；音箱上的程序和记忆后台跟你用什么电脑无关。Windows 刷机可以参考 [xiaoai-agent 的 Windows 教程](https://github.com/stevenjoezhang/xiaoai-agent/blob/main/deploy/README.md)。我们没在 Windows 上试过。

## 手上没有能刷的音箱

还有一个思路，我们没试过：不刷音箱，把"实时语音 + 提示词 + 记忆后台"搬到能自己写程序的硬件上，比如用 ESP32 自己做的小音箱（可以参考开源项目 [xiaozhi-esp32](https://github.com/78/xiaozhi-esp32)）。设备那头要自己实现录音、放音、连火山；提示词和后台可以照搬。

## 给 AI 助手：移植时的规矩

- 拿到设备的命令行以后，先只读摸底，不改任何东西：
  - `uname -a`、`cat /proc/cpuinfo`：看系统和 CPU；
  - `cat /proc/mtd`、`df -h`：看分区和空间；
  - `ps`：看在跑哪些程序；
  - `arecord -l`、`aplay -L`、`cat /etc/asound.conf`、`amixer controls`：看录音、放音、音量。
- 对没验证过的设备：
  - 不写分区，不改启动参数（不 `saveenv`），不切换启动槽；
  - 任何写入之前，要有别人验证过的方法、读两遍一致的备份，并且用户明确说接受变砖风险。
- 一次只改一处，先在电脑上测通，再放到设备上。
- 设备上只往自己的程序目录写，不删原厂文件，不用通配符删除。
- 钥匙和密码不进聊天、日志和代码仓库。
