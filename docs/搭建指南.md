# 从原厂 OH2P 到豆包音箱

准备：Apple 芯片 Mac、原装 12V 电源、能传数据的 Type-C 线；米家 App 中音箱已联网且固件为 **1.62.2**；Mac 和音箱在同一个 Wi-Fi；音箱不在蓝牙音箱模式。只覆盖 OH2P、boot_part=boot0 且 boot0 与此 OTA 一致的情形。其他型号、版本、boot1、USB 多台或换端口都停止，到项目 GitHub 提 Issue。

先下载本项目并在仓库根目录打开终端。让 Agent 按下面顺序执行；每个脚本结束的倒数第二行为 `OK: ...` 或 `STOP: ...`，最后一行为 `NEXT: ...`。看到 STOP 就停止，不跳过校验、不自动重试。脚本默认打印设备操作；明确参数才执行。下载、配置、备份及日志在被 Git 忽略的 `.local/`，文件0600，目录0700；工具必须执行所以0700。固件解包树保留原厂权限用于重打包，外层.local不允许其他用户进入。

作者在一台音箱上做过原方法；通用脚本的只读流程已在作者一台已改装音箱上验证；刷写、安装和卸载仍未在真机验证，离线模拟不能代替真机结果。首次运行要有刷坏风险准备。Windows/Linux刷机未验证，可参阅[上游Windows说明入口](https://github.com/stevenjoezhang/xiaoai-agent/tree/main/deploy/flash-tool)。

## 01 检查 Mac（未在真机验证）

**你要做什么**：打开终端，进入下载的仓库。安装[Homebrew](https://brew.sh/)；缺依赖时复制脚本打印的安装命令，装完重跑。它不会自行安装。没有 Homebrew 时也可以使用已有工具：02 加 `--unsquashfs <工具路径>`，03 加 `--mksquashfs <工具路径>`，04 加 `--libusb <libusb-compat动态库路径>`；作者彩排就是这样准备工具的，01 本身仍会提示缺少 Homebrew。

**运行什么**：`bash setup/01-check-mac.sh`

**怎样算成功**：末尾 OK，进入02。只支持Apple芯片Mac。

## 02 下载原厂固件（已验证（作者一台音箱）；通用脚本未在真机验证）

**你要做什么**：Mac 保持联网。此时不用动音箱。

**运行什么**：`bash setup/02-get-firmware.sh`

**怎样算成功**：下载的小米CDN OTA通过MD5、SHA-256、容器布局及上游CRC检查；解出的rootfs内部型号OH2P、版本1.62.2，末尾OK。不是用米家刷这个文件。

## 03 生成专用 SSH 补丁（已验证（作者一台音箱）；通用脚本未在真机验证）

**你要做什么**：不用接线。不存在时会生成 `~/.ssh/xiaoai_doubao_rsa`（RSA4096私钥），请自行安全保管，不发给Agent聊天或提交仓库。镜像里只有公钥。

**运行什么**：`bash setup/03-make-patch.sh`

**怎样算成功**：`.local/root-patched.squashfs` 小于0x02800000，末尾OK。仅修改dropbear配置、两处authorized_keys、root/.ssh目录、rc.local，保留原厂功能。

## 04 准备刷机工具（已验证（作者一台音箱）；通用脚本未在真机验证）

**你要做什么**：Mac保持联网，01中libusb和libusb-compat已装好。不必操作音箱。

**运行什么**：`bash setup/04-get-flash-tool.sh`

**怎样算成功**：固定Khadas提交的update核对原始SHA-256，取arm64并链接本机Homebrew兼容库，末尾OK。

## Mac 的允许配件连接（已验证（作者一台音箱，2026-11-10））

macOS 发现新的 USB 设备时可能弹出“允许配件连接”；没允许之前，程序无法连接刷机设备，而刷机窗口很短，可能来不及点。开始 05 前，在“系统设置→隐私与安全性”里把“允许配件连接”临时改成解锁时自动允许（选项名称以系统为准），刷完改回原设置。不想改设置也可以：弹窗时点“允许”，即使这一次失败，下一次通常就能成功。

## 05 抓住刷机窗口（已验证（作者一台音箱）；通用脚本已在作者一台已改装音箱上验证（只读：抓窗口、备份、重启、按 MAC 找音箱））

**你要做什么**：音箱接原装12V电源，同时用能传数据的Type-C线接Mac。只接这一台OH2P，保持同一个USB端口。脚本默认等待最多2分钟。运行后看到 `READY_TO_PLUG`，把音箱DC电源插头拔掉，停 3 秒再插回；Type-C线不要拔。拔插电源后刷机窗口只有约1.6秒，靠脚本自动抓，人不用抢。第一次可能要试几次。

**运行什么**：`python3 setup/05-usb-connect.py --execute`

**怎样算成功**：一台普通态0x2717:d002转为同端口0x1b8e:c003，立即identify 7成功，末尾OK。两台、换端口、超时都STOP。不要连续自行重试。

## 06 双读备份（已验证（作者一台音箱）；通用脚本已在作者一台已改装音箱上验证（只读：抓窗口、备份、重启、按 MAC 找音箱））

**你要做什么**：保持电源和Type-C不动，等待读取。备份含设备资料，不分享.local。

**运行什么**：`bash setup/06-backup.sh --execute`

**怎样算成功**：boot_part真假测试校准成功；boot0/boot1按Android头加512字节尾部读取，system0/system1各读40MiB已知范围，两遍哈希一致；boot0等于OTA boot，system0开头等于OTA rootfs，末尾OK。这里的system备份为已知40MiB范围，不声称读取了其他分区。如果仅想备份，接着运行 `bash setup/07-flash.sh --reset-only --execute` 正常开机，不刷写。

## 07 写 system0（已验证（作者一台音箱）；通用脚本已在作者一台已改装音箱上验证（只读：抓窗口、备份、重启、按 MAC 找音箱））；刷写未在真机验证

**你要做什么**：决定是否接受刷坏风险。保持供电和USB不动。中途不想刷，使用reset-only正常开机。

**运行什么**：先 `bash setup/07-flash.sh` 看命令；决定刷写时 `bash setup/07-flash.sh --i-accept-brick-risk`。只退出刷机模式：`bash setup/07-flash.sh --reset-only --execute`。

**怎样算成功**：复查boot0与备份，只写一次system0；按镜像长度读回哈希一致才reset。失败STOP，不重试、不切槽、不saveenv；读回不符时不会reset。boot1直接STOP并提Issue。

## 08 找到音箱并验证 SSH（已验证（作者一台音箱）；通用脚本已在作者一台已改装音箱上验证（只读：抓窗口、备份、重启、按 MAC 找音箱））

**你要做什么**：等音箱开机连上Wi-Fi。在米家App打开音箱→右上角设置→设备信息，抄下MAC（页面名称以App为准）。核对脚本打印的SSH指纹，首次记录在.local/known_hosts。既有记录不符必须停止。

**运行什么**：`bash setup/08-find-speaker.sh <米家App里的MAC>`。已经改装过：追加 `--key <原私钥路径> --known-hosts <原主机记录文件>`；09、10也带相同参数。后两步会复用08发现的地址。

**怎样算成功**：专用密钥StrictHostKeyChecking登录成功，读出OH2P、1.62.2、/proc/mtd及/data空间，末尾OK。

## 09 开通并安装（已验证（作者一台音箱）；通用脚本未在真机验证）

**你要做什么**：按[火山引擎开通](火山引擎开通.md)自己创建Key，不要贴到聊天。在火山控制台点“复制”，然后在Mac终端运行 `umask 077; mkdir -p .local; pbpaste > .local/volc_key; chmod 600 .local/volc_key`。这条命令不会把Key显示出来，Agent也看不到；不要把Key贴进聊天。安装并启动后唤醒聊天会按火山账单收费。准备孩子英文名。

**运行什么**：先 `bash setup/09-install.sh --check-only`（只读，不下载或生成配置）；再 `bash setup/09-install.sh --execute --child Amy --child Ben`。默认下载v0.1.0固定哈希包；发布前或离线包用 `--package <本地tar.gz>`。权重/词表和CA仍需在Mac从官方源下载。可选记忆后台部署见[server说明](../server/README.md)，用相同孩子昵称初始化，再加 `--memory-server https://你的后台 --device-secret-file <0600设备密钥文件>`；没给就关闭记忆。

**怎样算成功**：只往/data/xiaoai-plus写；空间超过安装包两倍；已有安装先备份到其rollback-日期目录；配置检查通过、启动进程和原厂mipns-xiaomi都在，启动日志0错误，打印安静3分钟CPU平均值（作者正常约80%）。最后对音箱说“豆包豆包”，再试“小爱同学”和米家控制。离线模拟跳过ARM运行不能证明这些通过。

**你要做什么**：决定只留原厂小爱，保持电源与网络可用，等待重启。无需删任何资料。

**运行什么**：`bash setup/10-uninstall.sh --execute`

**怎样算成功**：豆包停止，boot.sh改名，重启后原厂小爱进程仍在且豆包未启动；数据保留。不修改/etc。日后安装仍可使用原配置备份。

## 恢复原厂 rootfs（未在真机验证）

这与10停用豆包不同，会写system0。先确认原备份属于同一台OH2P、boot_part仍是boot0且boot0等于OTA；boot1、版本不符都STOP。备份和OTA rootfs均未在真机做过恢复演练，不能保证救砖。

重新执行05进入刷机模式。使用06的 `system0.1.bin` 时，从头截取SquashFS superblock偏移40处的64位小端bytes_used字节，检查hsqs魔数、能解包并确认OH2P 1.62.2，得到裸rootfs；不要把40MiB原始备份直接交给partition。或者直接选02的 `.local/extracted/root.squashfs`（官方OTA原件）。不要修改boot0、boot1、system1。

由Agent检查原备份双读哈希后，明确由用户接受刷坏风险，再用04得到的 `.local/update partition system0 <选定裸rootfs>` **一次**。随后 `.local/update mread store system0 normal <裸rootfs长度的十六进制> .local/restore-readback.bin`，精确长度和SHA-256相同才 `.local/update reset`。每条命令前核对唯一同端口WorldCup；可使用setup/firmware.py里的snapshot、boot_part、tool、read函数保持与07相同检查。任何失败停止，不重试、不切槽、不saveenv。恢复后SSH补丁和开机钩子消失，小爱应正常使用，/data资料仍在。

以后在米家App里接受小米固件升级，改装会被覆盖：豆包没了，小爱照常。想恢复豆包需重新核对固件是否仍受支持，再走一遍；不是1.62.2就STOP提Issue，不直接套本指南。
